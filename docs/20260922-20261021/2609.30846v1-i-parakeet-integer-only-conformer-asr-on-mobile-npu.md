## 摘要
本文提出 I-Parakeet，这是 NVIDIA Parakeet-CTC（0.6B 参数）的纯整数实现，可在智能手机 NPU 上运行，无需任何浮点算子或 CPU 回退。现代 Conformer ASR 模型因规模较大而难以部署到边缘设备，且量化模型在数值敏感操作上仍会回退到浮点，这使其无法充分利用移动 NPU 等整数加速器。为此，我们有三方面贡献。首先，我们推导了 Conformer 核心中相对位置自注意力的整数形式。我们将其两个具有不同量化尺度的分数分支以及相对位移融合为纯整数运算。其次，我们引入一种极小极大优化的 Swish 近似，使 Swish 输出的最大误差最小化。第三，对激活值进行逐层范围分析，得到两项针对性补救措施：对 BatchNorm 输出采用 INT16 网格，以及对重尾的编码器前激活采用百分位校准。I-Parakeet 在 LibriSpeech test-other 上取得 4.97% 的 WER，在 Qualcomm NPU 上以 0.048 的实时因子运行，比 CPU 基线快 7.5 倍。

## Abstract
In this paper, we propose I-Parakeet, an integer-only implementation of NVIDIA's Parakeet-CTC (0.6B parameters) that runs on a smartphone NPU without any floating-point operator or CPU fallback. Modern Conformer ASR models are hard to deploy on edge devices because of their size, and quantized models still fall back to floating point for numerically sensitive operations. This prevents them from fully exploiting integer accelerators such as mobile NPUs. To achieve this, our contributions are threefold. First, we derive an integer formulation of the relative-positional self-attention at the core of the Conformer. We fuse its two score branches with different quantization scales and the relative shift into integer-only operations. Second, we introduce a minimax-optimized Swish approximation that minimizes the maximum error of the Swish output. Third, a layer-wise range analysis of activations yields two targeted remedies: an INT16 grid for the BatchNorm output and percentile calibration for the heavy-tailed pre-encoder activations. I-Parakeet achieves 4.97% WER on LibriSpeech test-other, running on a Qualcomm NPU at a real-time factor of 0.048, 7.5x faster than a CPU baseline.

## 2. 方法论

### 2.1 整体量化框架

- 所有张量采用**均匀对称量化**：`qx = round(clip(x, -αx, αx) / Sx)`，其中 `Sx = αx/(2^(b-1)-1)`；激活逐张量一个 αx，权重逐通道一个 αx；默认位宽 b=8。
- 线性层仅需整数运算：INT32 累加后经预计算定点乘数 `m = round(2^n · SW·Sx/Sy)`（n=16）与右移完成重量化，运行时不出现实数比值、无除法、无浮点。
- 卷积同理；BatchNorm 折叠进前置 depthwise 卷积；LayerNorm 与 Softmax 复用 I-BERT 的整数核。

### 2.2 整数相对位置自注意力（Section 3.1）

- **问题**：注意力分数分解为内容分支 `Ac = (Q+1uᵀ)Kᵀ` 与位置分支 `Ap = Φ((Q+1vᵀ)Pᵀ)`，两者独立校准后尺度 `Sc ≠ Sp`，整数张量 `qc + qp` 不能表示 `Ac + Ap`；且相对位移 Φ 与零填充交织。
- **解法**：将“尺度转换 + 分支相加 + `1/√dk` 缩放”**融合为一次重量化**：
  - `qs = round(2^(-n) · (mc·qc + mp·Φ(qp)))`，其中 `mc = round(2^n·Sc/(Ss√dk))`、`mp = round(2^n·Sp/(Ss√dk))`。
- **两项工程优化**：
  - P 仅依赖序列长度，可离线量化为 INT8 常量 `qP`；
  - Φ 只搬移数值并插零、不做算术，满足 `Φ(S·q) = S·Φ(q)`，因此可直接对整数张量施加 Φ，实现为**静态索引映射**。

### 2.3 极小极大优化整数 Swish（Section 3.2）

- Swish `sw(x)=x·σ(x)` 中的 sigmoid 无整数核，沿用“二阶多项式拟合 tanh”的思路：`tanh(u) ≈ sgn(u)·[a(min(|u|,c)-c)²+1]`。
- **两点洞察**：
  1. L2（最小二乘）对所有 x 一视同仁，但 Swish 中 σ 被 x 相乘，大 |x| 处误差被放大（x=4 处同样 σ 误差是 x=0.1 处的 40 倍），故应优化 **L∞**；
  2. 拟合 tanh 最优的系数不等于拟合 Swish 输出最优的系数，应**直接对 Swish 输出拟合**。
- **目标函数**：`(a*, c*) = argmin_{a,c} max_x |sw(x) - ŝw(x; a,c)|`，数值求解得 `a* = -0.1240`、`c* = 2.4632`。

### 2.4 逐层激活范围分析（Section 3.3）

- 用校准数据（LibriSpeech dev-other）剖析全部激活范围，发现默认“b=8 + min-max”在两处失效：
  - **BatchNorm 输出**：系数 `γc/√(σ²c+ε)` 的通道间 max/median 比在部分层超过**四个数量级**，逐张量 INT8 网格被少数极端通道占满 → 该处改用 **INT16 逐张量**网格；
  - **预编码器激活**：max 与 p99.9 之比达 **11–21×**（编码器内部仅 2–3×），min-max 会把大部分 INT8 量化级浪费在 0.1% 的尾部 → 预编码器用 **p99.9 百分位校准**，编码器保持 min-max（即“混合缩放”）。
- 其余张量全部保持 INT8，以兼顾 NPU 吞吐。

## 6. 主要结论与发现

- **可行性结论**：现代大型 Conformer ASR（0.6B）**无需任何浮点推理**即可在手机 NPU 上端到端运行。
- **真机结果**：I-Parakeet 在 LibriSpeech test-other 上 WER **4.97%**，RTF **0.048**，峰值内存 **612 MiB**；相比 CPU FP16 基线（RTF 0.36）**快 7.5×**，峰值内存**降低约 60%**，WER 代价为 **1.21 个百分点**。
- **加速来源归因**：CPU 上仅权重量化（INT8 权重/FP32 计算）几乎不提速（0.36 → 0.42），说明收益来自 **NPU 上的整数计算**而非权重变小。
- **原生工具链不可用**：Stock FP16 与 Stock INT8 PTQ 在 NPU 上均得到 **100% WER**——FP16 失败与预编码器激活超出 FP16 范围一致；INT8 失败说明**工具链级 PTQ 不足以支撑该模型**，必须做针对性设计。
- **模拟结果**：test-clean 2.61%、test-other 5.32%、Common Voice 14.70%，分别比 FP32 落后 0.74/1.56/4.15 点；相比 Naive INT8 恢复 0.40/1.06 点（即两项范围补救的贡献）。
- **消融结论**：
  - Swish 近似的最大输出误差排序与 WER 排序完全一致（L∞ 拟合 Swish 0.039→5.32 最优；Hard-Swish 0.142→6.33 最差），**L∞ 优于 L2、拟合 Swish 优于拟合 tanh，两者独立贡献**；
  - BatchNorm 输出用可部署的逐张量 INT16 达 5.32，距不可部署的逐通道 INT16（5.29）仅 0.03 点，远优于逐张量 INT8（5.91）；
  - 混合缩放优于全局 min-max（5.32 vs 5.64），而全局 p99.9 显著变差（8.03），说明**裁剪只在重尾分布处有益**。
- **模拟与真机的差异**：真机 WER（4.97%）略低于模拟（5.32%），原因是 NPU 用**硬件查找表**计算 Swish

（硬件 LUT 的近似精度高于本文的多项式拟合），而非模拟中使用的多项式近似，说明模拟结果是保守估计。

- **部署属性结论**：最终模型在 NPU 上无任何浮点算子、无 CPU 回退，全部数值敏感算子（LayerNorm、Softmax、Swish、BatchNorm）均已整数化或折叠，满足纯整数推理的硬性约束。

## 8. 对后续研究的启发

- **“可部署性”应作为量化方法的一等约束**：本文的核心方法论贡献不在于单个算子近似，而在于把“NPU 是否支持该量化粒度”作为设计前提（例如逐通道 INT16 精度更好但因硬件不支持而被排除，改用逐张量 INT16）。这提示后续量化研究应在精度–可部署性二维平面上报告结果，而非只追求模拟精度。
- **融合重量化是整数化的通用技巧**：将“尺度转换 + 分支相加 + 常数缩放”合并为一次定点乘加与右移，避免了中间实数与多次舍入，可推广到其他多分支结构（如 Conformer 的残差 + dropout、门控单元）。
- **近似目标应与下游损失对齐**：Swish 的案例表明，算子近似的优化目标（L∞ vs L2）和拟合对象（拟合 Swish 而非其内部 tanh）都会实质影响 WER，且最大输出误差可作为 WER 的有效代理指标。这一“代理指标 + 直接拟合目标函数”的范式可迁移到 GELU、SiLU、Mish 等其他非线性。
- **逐层激活统计是低成本高回报的诊断手段**：仅通过一次前向的激活范围分析，就定位了 BatchNorm 通道间极差与预编码器重尾两个失效点，并据此设计“混合缩放”。建议将此类逐层范围剖析作为量化流程的标准步骤。
- **“工具链原生 PTQ 失败”本身是有价值的负结果**：官方 INT8/FP16 转换均得 100% WER，说明通用 PTQ 流程对大型 Conformer 不够，需要模型特定设计；这为工业界“为什么需要自定义量化”提供了实证依据。
- **硬件 LUT 与算法近似的互补**：NPU 硬件 LUT 精度优于多项式近似，提示算法侧可用较粗近似做设计空间探索，而部署时交由硬件 LUT 获得额外收益；未来可研究“算法近似 + 硬件 LUT”的联合优化。
- **纯整数推理的边界条件已被打开**：本文证明 0.6B 级 Conformer 可在手机 NPU 上无浮点运行，下一步自然的问题是：更大模型（>1B）、流式/在线 ASR、多语种与说话人分离等任务是否同样可行，以及在无浮点单元的 MCU 级设备上的可行性。

## 9. 总体评价

- **贡献定位**：本文是一篇**系统与部署导向**的工作，其价值主要在于“首次在消费级手机 NPU 上实现 0.6B Conformer 的纯整数端到端推理”，并以真机 WER/RTF/内存三项指标和“无浮点、无 CPU 回退”的硬性属性予以验证；方法层面的创新（融合重量化、minimax Swish、混合缩放）均为服务于该目标的具体工程–算法设计。
- **方法严谨性**：算子近似与范围校准的设计有清晰的动机推导（L∞ 因 σ 被 x 放大；BatchNorm 通道极差四个数量级；预编码器 max/p99.9 达 11–21×），消融将两个正交因素分离验证，并给出最大输出误差与 WER 排序一致的佐证，逻辑链条完整。
- **证据强度**：真机实验是本文最强证据，尤其是 Stock FP16/INT8 均 100% WER 的对照，有力支撑了“必须定制量化”的主张；但单设备、单次运行、缺能耗数据、缺同类系统同条件对比，使结论的外部有效性受限。
- **写作与可复现性**：量化公式、定点乘数构造、多项式系数（a*、c*）均给出，复现路径较清晰；但校准集规模、图编译细节、RTF 测量协议、功耗等部署关键细节缺失，复现门槛仍偏高。
- **适用场景**：适合资源受限的边缘/移动端 ASR 部署，尤其是无浮点单元或希望完全卸载到 NPU 的设备；对精度极度敏感或域外数据为主的应用，4.15 点的 Common Voice 差距需谨慎评估。
- **一句话总结**：I-Parakeet 以“可部署性优先”的设计哲学，把 0.6B Conformer 的全部数值敏感算子整数化，在手机 NPU 上以 1.21 点 WER 代价换取 7.5× 加速与约 60% 内存下降，填补了“纯整数 Conformer 能否真正跑在移动 NPU 上”的空白，但其跨平台可移植性、域外鲁棒性与能效证据仍待补强。
