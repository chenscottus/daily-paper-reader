## 摘要
基于单片三维（M3D）DRAM的存内计算（PIM）是应对数据密集型动态规划（DP）中内存墙问题的一种有前景的方案，但如今要发挥其性能仍需手写内核：程序员必须选择分块大小、将数据放置到具有非均匀延迟的存储层级上、在异构处理单元之间划分工作，并手动插入正确的广播与队列。我们提出GenMLIR，这是一种MLIR编译器，可为层级感知的三维PIM自动完成这一映射。GenMLIR将半环广义网格更新——全源最短路径（APSP）与序列比对所共享的代数形式——编码为一等IR抽象，并通过四个感知GenDRAM的pass组对其进行lowering，分别推导分块划分（blocked tiling）、层级感知放置、瓦片到处理单元的分配以及显式通信。我们还精确刻画了该抽象可接纳哪些DP递推、不可接纳哪些。在GenDRAM架构上，GenMLIR生成的代码相比无编译器支持的lowering，在APSP上最高快5.8倍、在序列比对中最高快16.7倍，并比我们也实现的一种标准仿射分块PIM编译器快1.2–1.4倍，达到可达性能上界的90–100%。它用4–9行代码即可表达这些工作负载，而非300–500行，且编译时间仅占运行时可以忽略的一部分。

## Abstract
Processing-in-Memory (PIM) on monolithic 3D (M3D) DRAM is a promising answer to the memory wall for data-intensive dynamic programming (DP), yet extracting its performance today demands hand-written kernels: the programmer must pick a tile size, place data across non-uniform-latency memory tiers, partition work between heterogeneous processing units, and insert the right broadcasts and queues by hand. We present GenMLIR, an MLIR compiler that automates this mapping for tier-aware 3D PIM. GenMLIR encodes the semi-ring generalized grid update, the algebraic form shared by all-pairs shortest path (APSP) and sequence alignment, as a first-class IR abstraction, and lowers it through four GenDRAM-aware pass groups that derive blocked tiling, tier-aware placement, tile-to-PU assignment, and explicit communication. We also characterize precisely which DP recurrences the abstraction admits and which it does not. On the GenDRAM architecture, GenMLIR-generated code runs up to 5.8 (APSP) and 16.7 (alignment) faster than a lowering without compiler support, and 1.2-1.4 faster than a standard affine-tiling PIM compiler we also implement, reaching 90-100% of an achievable-performance bound. It expresses these workloads in 4-9 lines instead of 300-500 and compiles in a negligible fraction of runtime.

# 论文总结：Compiling Semi-Ring Dynamic Programming to Tier-Aware 3D-DRAM Processing-in-Memory

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：单片三维（M3D）DRAM 将逻辑裸片直接键合在多层 DRAM 堆叠之下，可向近存储体计算单元提供数十 TB/s 的内部带宽，被视为缓解数据密集型动态规划（DP）内存墙的重要方向。GenDRAM 是这一方向的代表性硬件：8 个延迟层级（tRCD 2.29–22.88 ns，行访问延迟相差 1.6 倍）、16 通道 × 2 bank-group 共 32 个处理单元（PU，8 个 Search PU + 24 个 Compute PU）、环状互连，并支持广播与流水两种执行模式。
- **核心痛点**：硬件能力已超出软件能力。当前要发挥 GenDRAM 性能必须手写内核，程序员需手工完成：选定分块大小以适配片上 SRAM 预算；将延迟敏感表固定到快速层级、将带宽型张量跨通道交织；按模运算规则把瓦片映射到 PU 以避免邻居 bank 冲突；按递推关系手工插入广播、屏障与队列。这种代码不可移植，更不可复用——一旦更换递推，就必须推倒重来（手写映射约 300–500 行）。
- **关键洞察**：APSP（Floyd–Warshall）与序列比对（Smith–Waterman）在代数上是同一个半环网格更新，仅算子对 (⊕,⊗) 与遍历方式不同。GenDRAM 与 GraphBLAS 社区已用该同构性论证单一硬件基底；本文进一步论证它同样支撑**单一编译策略**——分块、依赖、放置、通信决策均与具体半环无关，工作负载相关的只有执行模式。
- **整体含义**：论文提出 GenMLIR，将半环 DP 抽象作为一等 IR，自动化完成面向层级感知 3D PIM 的映射，把"手写映射"转变为"编译器推导"，从而降低编程门槛并实现可复用、可扩展的 DP 编译流程。

## 2. 方法论

### 2.1 核心思想
- 以 MLIR 为基础设施，把半环广义网格更新 `D[i,j] ← D[i,j] ⊕ (D[i,k] ⊗ D[k,j])` 编码为一等抽象 `dp.grid_update`，并配合暴露层级、通道、bank-group、PU 类别与通信原语的 GenDRAM 设备方言，使放置与调度成为 IR 重写而非手工编辑。
- 整体流程分三阶段：**前端**（GenDSL 声明式语言，含 Algorithm / Data / Configuration 三段）→ **中端**（四个 GenDRAM 感知 pass 组）→ **后端**（设备 API 与命令流发射）。

### 2.2 关键技术细节（四个中端 Pass 组）
- **G1 DP 识别与归一化**：模式提取把标量 add/compare/select 嵌套替换为带半环标注的单一 `dp.grid_update`，再规范化循环边界、索引表达式与边界处理，保证后续变换不依赖输入语法细节。
- **G2 分块与依赖形成**：**不把分块大小 B 当作调参**，而是由容量模型推导——阻塞更新工作集为 3 个 B×B 瓦片，需满足 `3wB² ≤ S`，故 `B* = ⌊√(S/3w)⌋`。GenDRAM 上 S=768 KB（256 KB 共享暂存 + 16×32 KB PE 本地），32 位 APSP 数据下 B*=256。随后按算子签名物化两种依赖结构：APSP 的三阶段阻塞 Floyd–Warshall（pivot / 行·列 / 内部），或比对的 seeding + alignment 两核与对角波前顺序。
- **G3 映射与层级感知放置**：模式选择记录广播或流水为模块属性；瓦片到 PU 按 `PU(i,j) = (i×M+j) mod (C×G)` 分配；放置按延迟敏感度 `σ(o) = a(o)/β(o)`（依赖型指针追逐访问与流式字节之比）降序贪心分配到最低可用层级。PTR/CAL 表 σ≫1 占快速层级，距离矩阵与读缓冲 σ≈0 则跨上层通道交织以最大化 bank 并行度——把 GenDRAM 手工放置复现为策略输出而非常量。
- **G4 通信与同步综合**：由所有权 + 依赖边推导通信。APSP 发射 pivot 瓦片广播与三阶段屏障；比对发射 Search→Compute 的队列 send/recv，队列深度由建模的 seeding/alignment 吞吐比决定，估计不确定时暴露为运行时参数。

### 2.3 后端
- 通用步骤：bufferization（瓦片落入 G3 指定的内存空间）、PE 映射（8192 位行激活块，APSP 瓦片行 256×32 位，每 PE 取 512 位切片）、指令选择（由 G1 半环算子对选择 Max/Min 子单元，而非固定 opcode 序列）。
- 命令流发射：为每个 PU 生成内存布局（层级/通道/bank-group）与执行调度，交错内存命令（ACTIVATE、1024 位混合键合读、precharge）、数据通路命令与 G4 消息，受两条约束——行在其全部读完成前保持打开；调度遵守 FW 阶段屏障与队列深度上界。

### 2.4 抽象的可接纳范围
- 可接纳条件三条：(a) ⊕ 结合且交换、⊗ 对其可分配；(b) 依赖模式对循环索引仿射；(c) 单元更新控制流数据无关（存在静态调度）。
- 表 1 列出 7 个合格问题：APSP、SW 比对、编辑距离、传递闭包、最宽路径、minimax 路径、Viterbi——共用同一 pass 流水线，仅算子对与遍历不同。
- 明确排除三类：数据相关控制流（X-drop / 自适应带比对，违反 c）、非网格依赖图（矩阵链括号化、树形 DP，违反 b）、非结合累加（定点概率打分，违反 a）。

- **性能**：相对 B0，APSP 加速 5.2/5.2/5.8×（几何均值 5.4×），达吞吐上界的 90%，在 OSM 上达到上界；比对随读长增长加速 2.8→9.9×（PacBio）与 4.1→16.7×（ONT），全程位于关键路径上界（B3/B2

的比值随读长增加而上升，ONT 错误模型下更接近 100%，作者归因于比对在长读段下计算密度更高、内存墙压力相对较小，故调度质量更容易转化为实际吞吐）。

- **内存行为**：阻塞式 Floyd–Warshall 的 DRAM 流量随分块大小呈先降后升的 U 形，最优点与容量模型推导的 B\*=256 吻合，验证了"分块大小由 `3wB² ≤ S` 解析决定而非调参"这一设计选择的有效性；表 2 显示 PTR/CAL 等延迟敏感结构确实获得了高比例的快速层级驻留时间（T0 residency），而距离矩阵与读缓冲的访问主要落在交织后的高并行通道上。

- **编译开销**：编译时间相对被编译程序的模拟运行时间约为 10⁻⁶ 量级，可忽略；分解显示开销主要集中在 G3 放置与 G4 通信综合（涉及层级/通道搜索与队列深度建模），G1/G2 相对廉价。

## 7. 批判性审视（方法可信度与潜在问题）

- **论点的强度分层**：论文最强的证据是"两个代数同构负载共用同一 pass 流水线且都接近各自上界"，最弱的环节是"7 个合格问题均可接纳"——后者由可接纳条件（结合交换、仿射依赖、数据无关控制流）与分析性论证支撑，但仅 2 个问题有端到端数据，其余 5 个（编辑距离、传递闭包、最宽路径、minimax 路径、Viterbi）为外推。考虑到这 5 个问题在依赖结构与算子性质上与已评估的两者高度同族，外推风险不高，但仍属未验证声明。
- **上界 B2 的构造性**：APSP 的 B2 是 32-PU 吞吐极限，比对的是波前关键路径界。前者较硬（受 PU 数与每 PU 最小工作量约束），后者在实现上接近"关键路径即最优调度"的理想化假设，因此"达到 90–100% 上界"在比对场景中的说服力弱于 APSP。若 B2 本身偏松，则"接近上界"可能同时高估了绝对效率与相对 B1 的增益幅度。
- **B1 的对等性存疑**：B1 由作者自行实现，其调优投入与 GenMLIR 历经多轮迭代的工程成熟度难以对等；标准仿射分块编译器在缺少层级模型与 PU 特化时本就不具备可比表达力，因此 B3/B1 的差距更应读作"有/无层级与通信模型"的定性差距，而非精确的编译器质量比。
- **模拟器与规模**：周期精确模拟天然限制问题规模（最大 65k 节点、10 kbp 读段），与真实基因组/图分析负载（百万级节点、百 kbp 读段）差距明显；论文未报告模拟时长与重复次数，统计口径（是否单次运行、是否含 warm-up）不明确，性能数字的方差未知。
- **模型参数的敏感性**：`σ(o) = a(o)/β(o)` 的延迟敏感度、队列深度的吞吐比估计等均为建模量，论文报告了"估计不确定时暴露为运行时参数"的工程退路，但未给出敏感性扫描（如 σ 排序扰动对放置决策与性能的影响），因此放置策略的鲁棒性证据偏薄。
- **缺失的关键对照**：无周期级手调专家内核（作者自认是未来工作），也无与其他 PIM DP 编译器/框架（如面向 UPMEM、HBM-PIM 的 DP 工作）的横向对比，故"GenDRAM 上最优"的结论限于自建基线族内。

- **方法论启示**：把"分块大小"从超参数变为容量约束的闭式解、把"数据放置"从常量表变为延迟敏感度排序的贪心输出，是本文最具迁移价值的两点——它们把硬件相关的经验知识编码为可复用策略，使编译器在更换堆叠层数、tRCD 分布或 PU 配比时只需改设备方言与容量/延迟模型，而非重写 pass。
- **抽象层次启示**：以半环广义网格更新作为一等 IR 节点，等价于在 DP 领域复制 GraphBLAS 在稀疏线性代数中的成功路径；本文的增量在于证明该抽象不仅统一了算法表达，还统一了**映射决策**，这是"算子无关"与"策略无关"的区别。
- **可延伸工作**：(1) 补齐剩余 5 个合格问题的端到端数据，特别是控制流仍数据无关但依赖更复杂的 Viterbi；(2) 引入周期级手调专家内核作为硬基线；(3) 对 σ 与队列深度做敏感性分析并给出自动标定方法；(4) 将可接纳条件形式化为静态检查（在 G1 阶段即拒绝非仿射依赖或非结合算子），把"可接纳范围"从论文声明变为编译器保证；(5) 扩展到多裸片/多堆叠的跨器件放置，检验策略在更大层级空间下的可扩展性。

## 9. 总体评价

本文是一篇"以抽象统一性换取工程可复用性"的编译器系统论文：其核心贡献不在于单项优化（分块、放置、通信各自都有先例），而在于论证并实现了一条**与半环无关的端到端编译路径**，把 GenDRAM 这类层级异构 3D PIM 上 300–500 行的手写映射压缩为数十行声明式描述，并在两个代表性负载上达到可达上界的 90% 以上。方法的严谨性体现在容量模型闭式推导、依赖结构按算子签名物化、放置策略由可解释的延迟敏感度驱动；证据的薄弱处在于问题覆盖（2/7 实测）、基线对等性（自建 B1、解析 B2）与规模（模拟器受限）。总体而言，论文成功地把"半环同构 ⇒ 单一编译策略"从一句有吸引力的类比推进为可运行、可测量、可扩展的系统主张，为该方向确立了清晰的抽象边界与后续验证清单。
