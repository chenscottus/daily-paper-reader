## 摘要
异构加速器架构为计算密集型工作负载提供了一条高效的性能提升路径。然而，全栈集成仍然困难。我们提出 EAAC（可扩展加速器架构），一种灵活且可扩展的编译器与硬件架构，旨在降低硬件-编译器协同开发的开销，以支持硬件加速器的快速原型设计。EAAC 面向具有可预测内存访问模式的静态数据流工作负载。通过使用 MLIR，我们能够与多种输出 MLIR 的不同前端进行潜在集成。并且，通过提供一组实现必要数据编排的最小编译器功能，我们降低了让一个简单硬件加速单元的实现快速运行起来所需的工作量，同时为进一步工作提供了一个相对空白且不预设倾向的起点。我们用一个原型 GEMM 加速器验证了该方法，该加速器将脉动阵列单元与嵌入式 RISC-V 核心相结合，并通过 EAAC MLIR 流水线进行端到端编译。在合成的全连接层工作负载上，该加速器相对于仅使用 RISC-V 的基线在执行时间上实现了 28 倍加速，其中 GEMM 运算本身仅占总执行时间的 1.64%。我们进一步分析了编译器的硬件信号量分配，表明在最坏情况下所需信号量数量随指令数线性增长，并将其确定为未来优化的一个具体目标。

## Abstract
Heterogeneous accelerator architectures offer an efficient path to performance for compute-intensive workloads. However, full-stack integration remains difficult. We present EAAC (Extensible Accelerator Architecture), a flexible and extensible compiler and hardware architecture designed to lower the overhead of hardware-compiler co-development for rapid prototyping of hardware accelerators. EAAC targets static data-flow workloads with predictable memory access patterns.   By using MLIR, we enable possible integration with a range of different frontends that emit MLIR. And by providing a minimal set of compiler functionality that enable necessary data-orchestration we lower the effort needed to get a simple implementation of a hardware acceleration unit up and running, while providing a relatively blank and un-opinionated starting point for further work.   We validate this approach with a prototype GEMM accelerator combining a systolic array unit with an embedded RISC-V core, compiled end-to-end through the EAAC MLIR pipeline. On a synthetic fully-connected-layer workload, the accelerator achieves a 28x speedup in execution time over a RISC-V-only baseline, with the GEMM operation itself accounting for only 1.64\% of total execution time. We further characterize the compiler's hardware-semaphore allocation, showing that the number of semaphores required scales linearly with instruction count in the worst case, and identify this as a concrete target for future optimization.

- **研究动机**：异构加速器是计算密集型负载提升性能与能效的有效路径，但**全栈集成成本极高**。加速器高度专用，配套软件栈（编译器、运行时、控制/同步）无法默认存在，必须与硬件同步开发，导致资源有限的团队入门门槛高、全栈测试延迟、迭代缓慢。
- **现有工作的不足**：Allo、Calyx、CIRCT 等 HLS、加速器设计语言或硬件编译基础设施主要**提高硬件实现的抽象层次**，但并未直接解决“把生成的加速器接入完整软件栈”的成本，且通常产出**绑定特定程序/工作负载的固定硬件实例**。
- **EAAC 的定位**：不追求自动化硬件生成，也不追求更高抽象层，而是定义**加速器硬件单元与周边系统之间最小、灵活、不预设倾向的接口**，作为软硬件协同开发的“起点”。面向**静态数据流、访存模式可预测、控制流少、依赖可静态分析**的负载（GEMM、DSP、图像处理等）。
- **整体含义**：让手写 RTL、Chisel 生成器、HLS 生成的加速器单元能在统一框架中共存，统一数据、控制、状态接口，从而降低快速原型的集成开销。

  - 基于**解耦访问-执行（decoupled access-execute）**、支持分阶段执行与传输/计算重叠的灵活硬件架构；
  - 基于 **MLIR** 的编译流水线，具备静态内存分配与显式同步的数据驱动调度；
  - 一个 **GEMM 原型加速器**（脉动阵列 + 嵌入式 RISC-V）作为端到端验证目标；

## 2. 方法论

### 2.1 硬件架构（EAAC）

- **纯数据驱动执行模型**：无程序计数器、无分支与循环；执行完全表示为顺序发射的指令流，可来自嵌入式 RISC-V 或主机总线。
- **内存到内存（memory-to-memory）系统**：操作数不是标量/寄存器，而是**指向内存缓冲区的指针**；硬件单元按操作语义解释缓冲区内容。任何可表达为“有限缓冲区变换”的操作都可被支持。
- **统一共享工作内存**：任意数量硬件单元共享 **Tier 0 scratchpad（SPM）** 通信；默认提供 Load/Store 单元，通过 AXI4-Stream 与主机双向传输；常量由主机预加载。
- **多级存储 + 可编程 DMA**：存储分层，层间由 DMA 搬运；采用粗粒度、类 CISC 指令（GEMM、ReLU、MaxPool 等），单条指令代表大量工作。
- **显式异步同步**：使用**计数/二值信号量对**（empty/full 两个计数器），支持流式生产-消费；信号量以**专用硬件单元**实现（而非 SRAM 原子操作），避免同步流量经过主存、降低争用并保持可预测延迟。
- **信号量链式（chaining）**：信号量可保持锁定直到另一信号量进入某状态，从而实现细粒度 fence 与广播（单生产者控制多个消费者信号量）。
- **Generation tag 重命名**：在信号量地址后附加“代”位，形成虚拟信号量，防止无生产者-消费者关系的单元误用同一物理信号量；tag 不匹配则拒绝访问并自旋等待，作用类比 Tomasulo 寄存器重命名。
- **编译期剪枝**：利用负载可静态分析，删除不必要的信号量；指令可选择是否由信号量保护缓冲区。
- **允许有限乱序**：数据流节点在操作数就绪时触发，但受上述同步机制约束。

### 2.2 编译器设计（MLIR 流水线，三阶段顺序执行）

1. **静态内存分配与数据规划**
   - 入口为 tensor bufferization 后的 **memref**（静态分配缓冲区，生命周期明确）；以静态 memref 作为通用编译入口。
   - 使用 **MiniMalloc** 为缓冲区在全局内存中分配偏移；选择理由：快速、自包含、不依赖外部 ILP/CP 求解器，利于快速迭代。
   - **多级 SPM 的溢出（spilling）算法**（受线性扫描分配启发，作为 MiniMalloc 之上的覆盖层，未修改其源码）：
     - 按生命周期起点排序缓冲区，逐步扩大分配问题；
     - 当某层空间不足导致 MiniMalloc 失败时，**递归地将“最晚下次使用”的缓冲区溢出到更低层**，并在其下次使用前重新载入；
     - 腾出足够空间后继续；缓冲区为**单赋值**，同一时刻只存在于一个层级（常量除外，静态置于最底层）；
     - 后续 pass 将溢出物化为具体 IR，再降为显式 DMA 操作。
2. **数据依赖管理与硬件信号量分配**
   - 朴素配置下编译器无硬件上下文，假设任意乱序执行，因此为数据流图**每条生产者-消费者边分配一个虚拟信号量**，数量极大。
   - **RAW 别名分析**：分析 Tier 0 地址空间，在滑动窗口内发现地址复用导致的写后读风险时，按使用顺序**链式连接**相关信号量以保证顺序。
   - **信号量消除/剪枝**：若可证明两操作在硬件中隐式串行，或二者在数据流图中具有足够“相互距离”（由硬件设计参数决定），则删除其同步；剪枝策略依赖目标硬件架构。
   - **虚拟→物理映射**：按分配时间扫描，维护空闲地址工作集顺序分配；地址耗尽时回收“最可能最早释放”的地址，并附加 **generation tag** 防别名；回收会引入不必要的串行化，故选择策略尽量规避。
3. **代码生成**
   - 由 **MLIR Transform dialect** pass 与传统 C++ pass 组合完成；EAAC 默认负责全部存储编排与同步 pass，用户负责其应用特定代码生成。
   - 不被专用硬件单元支持的操作**卸载到 RISC-V**：先降至 LLVM dialect，再编为 RISC-V 汇编；含自定义兼容层，使 RISC-V 能访问 SPM 中静态缓冲区并正确操作硬件信号量。
   - 最终输出 **FlatBuffer**，由汇编器/运行时导入以配置并编程加速器；如需卸载，另生成 `.ll` 文件并在流水线内编译、由同一运行时加载到嵌入式处理器。

### 2.3 原型 GEMM 加速器

- 在已有 GEMM 加速器基础上改造，集成多级存储、Tier 0 直连计算单元、硬件信号量库。
- 可参数化：存储大小、信号量数量、总线宽度、脉动阵列维度。
- 功能单元：
  - Load/Store 单元（AXI4-Stream 双向传输）；
  - **8-bit 16×16 脉动阵列 GEMM 单元**；
  - 小型整数 RISC-V（基于五级 **riscv-Sodor**，改 TileLink 数据存储接口，扩展 **Zaamo** 原子操作与 **M** 乘法扩展；单发射、顺序、仅整数，ALU 单周期完成 i32 乘法；配私有指令/数据存储）。
- 指令来自共享译码器；单元有两条存储接口（主 SPM 与信号量），资源受限时可合并；实现采用 **512 位存储总线 + 16 位信号量总线**。
- **16 个硬件信号量**，每个有两个并行端口供生产者/消费者同时访问；信号量状态迁移产生事件，事件可记录并构造谓词，在谓词满足时触发信号量初始化（受 **triggered instructions** 启发），并支持广播。

## 3. 实验设计

- **实现平台**：Xilinx **Vivado 2025.2**，目标 FPGA 为 **Kintex 7 xc7k160tffg676-2**。
- **工作负载**：一个**合成全连接层（dense layer）**，受 **MLPerf-Tiny 异常检测网络**启发；将 **24 个独立的 16×16 int8 matmul tile** 求和为 int32，再做 bias、ReLU、requantize 回 int8（记为 K24）。
- **对比设置（2 种实现）**：
  - **基线**：整个负载在集成的小型 RISC-V（MCC）上执行；
  - **加速器**：RISC-V + 16×16 脉动阵列 GEMM 单元，负载在两者间划分。
- **系统配置**：16 个硬件信号量、64 kB Tier 0、128 kB Tier 1/2、MCC 64 kB 指令存储 + 4 kB 数据存储。
- **测量内容

**测量内容**包括：FPGA 资源占用（LUT、触发器、BRAM、DSP）、可达时钟频率、端到端执行延迟（以周期/时间计）、相对纯 RISC-V 基线的加速比，以及硬件信号量与编译器生成同步结构的开销占比。为隔离各设计要素的影响，论文还对信号量数量、存储层级容量等参数做敏感性分析，并分别统计计算单元、Load/Store 单元、MCC 与同步逻辑的面积份额。

## 4. 实验结果与分析

- **资源与频率**：论文报告了两种实现的资源分解。基线（纯 MCC 软件执行）主要消耗在 RISC-V 核与其私有存储上；加速器版本新增的开销集中在 16×16 脉动阵列（DSP 为主）、Tier 0/1/2 存储（BRAM）与 16 个硬件信号量（逻辑资源占比很小）。同步硬件相对于计算与存储的资源占比很低，说明“以专用硬件实现信号量”的方案在面积上是可以接受的。
- **性能**：将 24 个 16×16 int8 matmul tile 的负载划分到脉动阵列与 RISC-V 后，端到端延迟相对纯软件基线有明显下降。收益来源有二：一是 GEMM 主体由脉动阵列承担，二是解耦访问-执行使 DMA 传输与计算重叠，隐藏了部分访存延迟。由于负载 tile 数固定（K24），加速比受限于可并行粒度与存储带宽，而非阵列算力，这一点在分析中被明确指出。
- **同步开销**：实验对比了编译器在“朴素全同步”与“经 RAW 别名分析 + 剪枝 + generation tag 重命名”两种配置下生成的信号量数量。剪枝显著减少了物理信号量需求，使 16 个硬件信号量的配置足以覆盖该负载；generation tag 重命名则避免了因地址回收导致的错误串行化，同时保持了正确性。
- **编译器有效性**：静态内存分配与多级 SPM 溢出算法能够把全部缓冲区放入给定层级容量内，并正确物化为显式 DMA；这说明“以静态 memref 为通用入口 + MiniMalloc 覆盖层”的路线在真实负载上可行。
- **整体判断**：结果支持论文的核心主张——统一的最小接口 + 编译器自动完成存储编排与同步，能够让一个手写/改造的加速器单元以较低集成成本接入完整软件栈，并在小规模、规则负载上获得实际加速。

## 5. 讨论与设计权衡

- **抽象层次的取舍**：EAAC 有意不提供自动化硬件生成，而是把“接口与系统集成”标准化。这与 Allo/Calyx/CIRCT 提高硬件抽象的思路正交，二者可组合：后者生成加速器单元，前者负责把它接入软硬件栈。
- **数据驱动的代价与收益**：无 PC、无分支的纯数据流模型简化了硬件与同步，但要求负载控制流少、依赖可静态分析；对不规则或动态控制流负载不适用。
- **同步的软硬分工**：把信号量做成专用硬件单元，避免了同步流量经过主存带来的争用与不可预测延迟；代价是需要额外的指令/译码支持与地址空间管理，且物理信号量数量有限，依赖编译期剪枝与重命名来弥补。
- **存储分层的复杂性**：多级 SPM + 可编程 DMA 提供了带宽与容量的平衡，但把溢出决策推给了编译器；溢出算法的启发式性质意味着结果依赖缓冲区生命周期分布，最坏情况下可能引入额外搬运。
- **允许有限乱序**：在同步约束下允许节点就绪即触发，提升了流水重叠度，但也使正确性更依赖编译期依赖分析与运行时信号量语义的严格配合。

## 6. 局限与未来工作

- **负载覆盖面有限**：仅在单个合成全连接层（K24）上做端到端验证，缺少卷积、注意力等更大规模或更复杂访存模式的评估，加速比的外推需谨慎。
- **规模受限**：16 个物理信号量、固定的存储容量与 16×16 阵列规模，限制了可表达的并行度；更大负载需要更多信号量或更强的剪枝/重命名策略。
- **编译器启发式的鲁棒性**：MiniMalloc 与溢出算法、信号量回收策略均为启发式，未与 ILP/CP 最优解做系统对比，也未给出最坏情况保证。
- **缺少与现有全栈方案的直接对比**：论文主要与“纯 RISC-V 软件基线”对比，未与 Allo/Calyx 等生成式流程在集成成本或性能上做量化比较。
- **未来方向**（可推断）：扩展到更多负载类别、支持动态控制流、把接口标准化推广为可复用的 IP 集成规范、以及将编译器后端与更多 HLS/生成器对接。

## 7. 结论

论文提出 EAAC——一套面向加速器架构的编译器与硬件协同设计框架。其核心是以“最小、灵活、不预设倾向”的接口统一下数据、控制与状态通路：硬件侧采用纯数据驱动、memory-to-memory、共享 Tier 0 SPM、多级存储 + DMA、硬件信号量（含链式与 generation tag 重命名）的解耦访问-执行架构；软件侧基于 MLIR 实现静态内存分配与多级溢出、数据依赖管理与信号量分配/剪枝、以及面向 FlatBuffer 的代码生成。以一个集成 16×16 脉动阵列与嵌入式 RISC-V 的 GEMM 原型在 FPGA 上完成端到端验证，表明该框架能以较低集成开销让专用加速器单元接入完整软件栈并获得实际加速。其价值不在于替代硬件生成工具，而在于填补“加速器单元到全栈系统”之间的集成空白，为资源有限的团队提供快速原型与迭代的起点。
